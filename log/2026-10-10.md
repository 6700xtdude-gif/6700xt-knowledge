# 2026-10-10 — Seeding the KB + verifying RX 6700 XT status

**Machine:** SANDBOX · Windows 11 Pro · RX 6700 XT `gfx1031`
(driver `32.0.21045.5002`) · Ryzen 5 5600 · 31.9 GB · 1 TB NVMe · no ROCm installed
**Goal:** Establish the project's "memory" — a public, dated, source-cited KB — and pin down the
current truth about the 6700 XT before installing anything.
**Result:** ⚠️ partial — KB seeded and committed; **llama.cpp Vulkan installed and detecting the
6700 XT**; benchmark run pending the model download.

## Context

This machine is a fresh, bare-metal sandbox. The motivating problem: fast-changing facts (ROCm
support, driver requirements, which engine uses Vulkan vs HIP) kept being re-derived, and stale
assumptions caused repeated wrong answers. Rather than freeze facts into model weights, we keep a
**dated KB** that can be cloned onto a future reimage (e.g. Arch/Omarchy) and extended there.

## Findings

- **ROCm does not officially support `gfx1031` on Windows.** AMD's own HIP SDK / runtime table
  (retrieved 2026-07-31) marks the RX 6700 XT **Runtime ❌ / HIP SDK ❌**; official support is
  RDNA 3/4 only. `Verified: 2026-07-31` `📄` `[S1]`
- **`HSA_OVERRIDE_GFX_VERSION=10.3.0`** remains the common workaround. `⚠️` `[S1]`
- **Vulkan needs no ROCm** and is the low-friction inference path on this card; LM Studio frequently
  picks the Vulkan engine here. `⚠️` `[S2]` `[S6]`
- **Native Windows HIP (no WSL)** is reported working (vLLM + ROCm 7.15, ~62 tok/s). `⚠️` `[S3]`
- **ROCm 7.14 requires Adrenalin 26.6.4+** on Windows. `⚠️` `[S3]`
- **Unsloth claims "Full" support for `gfx1031` on Windows** and auto-installs ROCm — contradicts
  AMD's table; must be verified locally. `📄` `[S5]`
- **Strata** lists the RX 6700 XT on an **experimental `--backend hip`** path, described as
  **"unvalidated" (#524)**; maintainers don't own the card. API on `127.0.0.1:8080`. `📄` `[S9]`
- **llama.cpp** now offers a **unified `llama` binary** with subcommands (`llama serve`) *alongside*
  the classic `llama-server.exe`. `📄` `[S4]`
- **WSL** is now open source and WSL containers went GA ~2026-09-29 — noted, but WSL stays a fallback
  for this project. `⚠️` `[S10]`

### Verified on this machine (2026-10-10)

- **llama.cpp Vulkan works with no ROCm.** Build `b11541` (`0.6.0-dev`, commit `f2918cabb`,
  Clang 20.1.8, Windows x64) reports:
  `Vulkan0: AMD Radeon RX 6700 XT (12272 MiB, 11474 MiB free)`. `✅` `[S4]`
- **Both server styles ship.** The unified `llama.exe` exposes subcommands
  `serve`, `cli`, `download`, `version`, `licenses`, `help`; classic `llama-server.exe` is also
  present. `✅` `[S4]`
- **Default server port is `9931`** on this build (not the old `8080`). `✅` `[S4]`
- **GitHub CLI** installed via winget: `gh 2.102.0` (`C:\Program Files\GitHub CLI\gh.exe`). `✅`
- **KB published**: public repo live at
  <https://github.com/6700xtdude-gif/6700xt-knowledge> (default branch `main`). `✅`
- **Hostname is `SANDBOX`** — the rename was sealed by a reboot (last boot 2026-10-10 11:22);
  `hostname`, active name, and pending name all read `SANDBOX`. `✅`
- **Vulkan device caps** (`llama-bench`, Vulkan): `fp16: 1 | bf16: 0 | fp4: 0 | warp size: 32 |
  matrix cores: none`. `✅` `[S4]`
- **4B inference on Vulkan works fast** — `qwen3 4B Q4_K_M`, `ngl 99`: **pp512 ≈ 1029 t/s**,
  **tg128 ≈ 96 t/s** (details in the benchmark file). `✅` `[S4]`

## Corrections to prior assumptions

- Earlier framing implied ROCm "works" on the 6700 XT; corrected — **officially it does not**, the
  override is a hack, and the supported path is increasingly Vulkan or bundled HIP.
- `Win32_VideoController.AdapterRAM` reports 4 GB here; **actual VRAM is 12 GB** (32-bit field wrap).
